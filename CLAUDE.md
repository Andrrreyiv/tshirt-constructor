плотность, цвет, сторона (перёд/спина), принт из библиотеки или свой файл, надпись,
итог заказа. Сдан и принят клиентом 02.08.2026, дальше идут доработки по его замечаниям.

⚠️ **НЕ ПУТАТЬ с `jetron-constructor`** — это конструктор футбольной ФОРМЫ (линейки
Champion/Legend). Тот же заказчик (jetronsport.ru), но отдельный продукт и отдельное репо.

## ⚠️ ГЛАВНОЕ ПРАВИЛО ДЕПЛОЯ: версия в адресе iframe
Страница 3686 встраивает конструктор как `<iframe id="jetronConstructor" src=".../tshirt/?v=ТОКЕН">`.
**Залить файлы НЕДОСТАТОЧНО.** Не сменил ТОКЕН в адресе — вернувшийся посетитель получает
из кеша и старый `index.html`, и все модули с тем же `?v=`, то есть ВСЮ старую сборку.
Отсюда рождается «я обновляю, а ничего не меняется».
- ⚠️ **id рамки менять НЕЛЬЗЯ**: скрипт авто-высоты сайта ищет именно `jetronConstructor`.
- Токен правится через REST `POST /wp-json/wp/v2/pages/3686` (текстового поля в редакторе
  нет, страница собрана билдером, токен лежит в `content.raw`). Нонс: `GET /wp-admin/admin-ajax.php?action=rest-nonce`
  — обычный nonce со страницы отдаёт `rest_cookie_invalid_nonce`.
- Перед патчем убедиться, что вхождение токена РОВНО одно и длина контента не меняется.
- Токен бампать и для ЛОКАЛЬНОЙ проверки: ESM кешируется по URL, `location.reload()` не лечит.
- **Текущий токен сборки: `20260825b`**, на странице 3686 поднят 25.08 (REST, статус 200,
  вхождение одно, длина контента 1230 не изменилась).
  ⚠️ Прежний живой токен на 3686 был **`20260801d`**, а не `20260825a`, как раньше врал этот
  файл. Поймано только тем, что перед патчем считали вхождения, а не меняли вслепую.
  Правило: считать `content.raw`, а не верить записи о токене.
- ⚠️ **Заливка идёт ТОЛЬКО из живого Chrome владельца** через расширение Claude in Chrome.
  `chrome-devtools` MCP не подходит: свой чистый профиль, сессии WP нет, антибот отдаёт капчу.

### Механика заливки (WP File Manager, elFinder)
- 1R AntiBot режет curl, работать через Claude in Chrome. PUT и DELETE у REST антибот тоже
  режет (отдаёт HTML со статусом 200), POST проходит.
- Текст: `cmd=put`, **без** `encoding=scheme`, ОДИН файл за вызов (батч отклоняется классификатором).
- `cmd=put` пишет только в СУЩЕСТВУЮЩИЙ файл: под новый сначала `cmd=mkfile`.
- Бинарники (шрифты, картинки) только `cmd=upload` с FormData и `overwrite=1`, target = хеш КАТАЛОГА.
- Проверять НАЛИЧИЕ в листинге `cmd=open`, а не HTTP-статусом: антибот отдаёт свою HTML-страницу
  (~17 КБ) со статусом 200 вместо 404.
- Сверка деплоя надёжнее всего по SHA-256 через `crypto.subtle` в браузере.
  ⚠️ Правило «первый байт 0 = порча» верно только для текстовых файлов: TTF законно
  начинается с `0x00` (сигнатура sfnt).

### 4. «Ползёт вниз, ползёт до бесконечности» — ДВЕ причины, обе закрыты
Клиент на видео: «Видишь, ползёт вниз, вот этот экран. Он ползёт, ползёт и он ползёт
до бесконечности». Локально без рамки авто-высоты дефект не воспроизводится вообще,
поэтому написан стенд `docs/iframe-harness.html`, буквально повторяющий поведение сайта
(`frame.style.height = высота документа внутри` каждые 100 мс, все замеры в `window.__замеры`).

**Причина A — окно библиотеки принтов.** Было `position: absolute`, а абсолютный элемент
входит в `scrollHeight`: прокрутили вниз → `top` вырос → документ стал выше → сайт увеличил
рамку → следующий кадр сдвинул окно ещё ниже. Лечение: `fixed` (`pinStyle` в `LibraryPanel.js`).
Внутри рамки своей прокрутки нет, `scrollY` всегда 0, поэтому на экране окно встаёт туда же,
но высоту документа больше не кормит.

**Причина B, ГЛАВНАЯ, найдена замером уже ПОСЛЕ правки A.** Страница ползла сама, без всякой
библиотеки, ровно на **16 px за кадр** (замер: 3766 → 3782 → 3798 → 3814 → …). Вся петля
была в одной строке CSS: у `body` стояло `min-height: 100vh`, а внутри iframe `100vh` это
высота САМОЙ РАМКИ. Сайт ставит рамке высоту документа → документ дотягивается min-height
до новой высоты рамки → `documentElement.scrollHeight` всегда на 16px больше `body` →
следующий кадр добавляет ещё 16. Строка удалена; фон не пострадал, потому что у `html`
своего фона нет и фон `body` по правилам CSS красит весь холст.

⚠️ **Стенд сначала мерил не то свойство и потому ничего не доказывал.** `body.scrollHeight`
абсолютный оверлей НЕ ВИДИТ вовсе — он остаётся 1977 даже при `top: 3000px`; растёт только
`documentElement.scrollHeight` (1993 → 3430). Стенд переведён на максимум из двух.
⚠️ И второе, тоже замером: `documentElement.scrollHeight` внутри рамки **не бывает меньше
высоты самой рамки**. Поэтому скрипт, меряющий его, рамку умеет только увеличивать. Пока
внутри есть хоть какая-то добавка сверх высоты окна — рост бесконечен; когда добавки нет,
получается неподвижная точка (замер: `html.scrollHeight` = `innerHeight` = 2139 ровно).

**Проверено в обе стороны, это главное:** после правки — 2011 px, ноль роста за 22 замера
в покое и ещё за 31 с открытой библиотекой при прокрученной странице, окно библиотеки
ложится ровно в экран (0…730 при экране 730). Контрольная проверка: временно вернули
`min-height: 100vh` — рост немедленно возобновился, 2027 → 2043 → 2059 → … → 2139,
+16 за замер, монотонно. Убрали — снова ноль. Тест-сторож `tests/OverlayPin.test.js`
не пускает `vh` обратно в высоту `body`.
⚠️ В превью-браузере `requestAnimationFrame` НЕ ТИКАЕТ вовсе (замер: 0 кадров), поэтому
привязка окна к прокрутке там выглядит сломанной. Это артефакт окружения: ручной
`dispatchEvent(new Event('scroll'))` мгновенно даёт расчётные значения. Не чинить.

  это DOM-узел `#app` и ловушка: `Object.keys` даёт `[]`, `state` = null.
- **Дескрипторы слоёв содержат `src` в виде data-URL.** `JSON.stringify` целого дескриптора
  выбивает лимит ответа (ловил 461 147 знаков). Фильтровать длинные строки до вывода.
- `location.reload()` внутри `preview_eval` убивает сам eval («Inspected target navigated»).
  Перезагрузка и замер — двумя отдельными вызовами.
- Живую правку поля ввода проверять НЕ значением, а тождеством узла
  (`document.querySelector(sel) === input`) и `document.activeElement`.
- Проверка синтаксиса через `new Function(код без import)` НЕ ловит дублирующийся импорт —
  он однажды уронил весь конструктор при зелёной проверке. Проверять загрузкой страницы.
- `Number(null)` даёт 0, а не NaN; `Number([1400])` даёт 1400. Пустая настройка молча
  превращалась в самое узкое поле.
- Замер тач-целей на 375px в браузере с МЫШЬЮ бессмысленен: `@media (pointer: coarse)`
  не активируется. Проверять через `matchMedia('(pointer: coarse)').matches`.
- Находимость элемента проверяется ГЕОМЕТРИЕЙ относительно обрезающего предка, а не
  доставкой событий: синтетика не видит `overflow: hidden` у родителя.
- Расшифровка видео и голосовых: `faster-whisper` (модель small, language=ru), ffmpeg из
  `imageio_ffmpeg`. Вывод писать в файл (кириллица в консоли ломается, `PYTHONIOENCODING=utf-8`).
- `cd` сбрасывается между вызовами Bash — пути абсолютные. Для curl `127.0.0.1`, не `localhost`.
- Edit требует предварительного Read того же файла.
- **Мост tdd-guard берёт ФАЙЛЫ, а не каталог**: `node .../node-report.mjs tests/` даёт
  `MODULE_NOT_FOUND`. Разворачивать глоб: `$(ls tests/*.test.js | tr '\n' ' ')`.
- **`javascript_tool` не ждёт промисов** — возвращает `undefined` или `{}`. Всегда в два
  вызова: первый кладёт результат в `window.__out` внутри `.then()`, второй читает
  `JSON.stringify(window.__out)`.
- **Ответ инструмента режется на строках с query string**: вернул адрес рамки с `?v=` —
  получил `[BLOCKED: Cookie/query string data]`. Возвращать только производные факты
  (числа, длины, булевы), а не сырые URL.
- **`file_upload` больше не принимает путь на диске**, требует содержимое в параметре
  `files`. Значит 200+ КБ base64 попадут в контекст: такую заливку делать СУБАГЕНТОМ.
- **Класс окна библиотеки — `libm`** (`libm__card`, `libm__cat`, `libm__cell`, `libm__thumb`,
  `libm__close`). Селектор `[class*="library"]` цепляет ЧУЖОЙ статичный элемент 74 px и даёт
  ложный вывод «position: static». Класс брать из `LibraryPanel.js`, а не из головы.
- `document.body` на странице wp-admin бывает `null` — писать защитно, иначе `TypeError`
  скрывает настоящую причину (например, что открыта форма входа).
